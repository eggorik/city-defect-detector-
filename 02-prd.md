# PRD: мониторинг инфраструктуры МГТС по фото

Короткий PRD для хакатона. Значения в квадратных скобках уточняем после ответов эксперта и выдачи данных.

## 1. Цель

Прототип находит объекты инфраструктуры МГТС на фото с камер служебных машин, оценивает их состояние и формирует список объектов, требующих проверки или ремонта, с привязкой к месту.

Метрики успеха:

- mAP@50 детекции объектов на проверочной выборке не ниже [0,6];
- полнота нахождения дефектов не ниже [0,8];
- медианная ошибка привязки к месту на проверочном маршруте не больше [10 м].

## 2. Пользователи

- **Инженер эксплуатации.** Получает список объектов и едет их проверять. Ему нужно понять, где объект, что с ним и насколько это срочно.
- **Диспетчер или планировщик работ.** Загружает кадры после объезда, смотрит общую картину и выгружает список в рабочие инструменты.

## 3. Главные сценарии

Приоритеты по MoSCoW: M обязательно, S желательно, C если будет время, W точно не сейчас.

## 4. Критерии приёмки

### US1. Загрузка кадров

1. **Дано:** папка или архив с JPG и PNG. **Когда:** пользователь загружает их. **Тогда:** все кадры приняты, интерфейс показывает их количество.
2. **Дано:** среди файлов есть повреждённый или не изображение. **Когда:** идёт загрузка. **Тогда:** этот файл пропущен с понятным сообщением, остальные обрабатываются.
3. **Дано:** у части кадров нет координат. **Когда:** загрузка завершена. **Тогда:** такие кадры помечены отдельно и не теряются.

### US2. Детекция объектов

1. **Дано:** проверочная выборка с разметкой. **Когда:** запускается оценка. **Тогда:** mAP@50 не ниже [0,6].
2. **Дано:** обработанный кадр. **Когда:** пользователь открывает его. **Тогда:** видны рамки найденных объектов с классом и уверенностью.
3. **Дано:** кадр без объектов инфраструктуры. **Когда:** он обработан. **Тогда:** записей объектов из него не появляется.

### US3. Оценка состояния

1. **Дано:** найденный объект. **Когда:** обработка завершена. **Тогда:** у объекта есть статус из списка: «норма», «дефект», «не удалось оценить».
2. **Дано:** объект со статусом «дефект». **Когда:** пользователь его открывает. **Тогда:** указан тип дефекта из согласованного списка [уточнить у эксперта] и короткое текстовое пояснение.
3. **Дано:** объект слишком мелкий, размытый или перекрыт. **Когда:** оценивается состояние. **Тогда:** статус «не удалось оценить», а не «норма».
4. **Дано:** проверочная выборка с разметкой состояния. **Когда:** запускается оценка. **Тогда:** полнота нахождения дефектов не ниже [0,8].

### US4. Привязка к месту и объединение кадров

1. **Дано:** кадр с GPS в EXIF. **Когда:** он обработан. **Тогда:** объекты на нём получают координаты кадра.
2. **Дано:** кадр без GPS, но есть трек машины. **Когда:** он обработан. **Тогда:** координаты берутся из трека по времени съёмки. Если ближайшая точка трека дальше [5 с] по времени, координаты помечены как неточные.
3. **Дано:** один и тот же объект виден на нескольких кадрах подряд. **Когда:** обработка завершена. **Тогда:** в списке одна запись с числом наблюдений. Объединяются объекты одного класса в радиусе [10 м].
4. **Дано:** у объекта несколько наблюдений с разным статусом. **Когда:** записи объединяются. **Тогда:** итоговый статус — худший из наблюдений.
5. **Дано:** проверочный маршрут с известными координатами объектов. **Когда:** запускается проверка. **Тогда:** медианная ошибка не больше [10 м].

### US5. Список объектов для проверки

1. **Дано:** обработанный объезд. **Когда:** пользователь открывает список. **Тогда:** в нём объекты со статусами «дефект» и «не удалось оценить», отсортированные по приоритету.
2. **Дано:** правило приоритета [согласовать: тип дефекта и уверенность модели]. **Когда:** считается приоритет. **Тогда:** у каждой записи приоритет «высокий», «средний» или «низкий», и правило описано в README.

### US6. Карта

1. **Дано:** обработанный объезд. **Когда:** пользователь открывает карту. **Тогда:** объекты отмечены точками, цвет зависит от статуса.
2. **Дано:** точка на карте. **Когда:** пользователь кликает на неё. **Тогда:** открывается лучший кадр объекта с рамкой, статусом и пояснением.

### US7. Выгрузка

1. **Дано:** список объектов. **Когда:** пользователь нажимает «Выгрузить». **Тогда:** скачивается файл с полями: ID, класс, статус, тип дефекта, приоритет, широта, долгота, точность координат, число наблюдений, время, имя лучшего кадра.
2. **Дано:** выгруженный CSV. **Когда:** его открывают в Excel. **Тогда:** кириллица отображается правильно.

## 5. Нефункциональные требования

- **Платформа:** веб-интерфейс на Streamlit. Запуск локально одной командой по README.
- **Скорость:** обработка одного кадра не дольше [1 с] на GPU. Демо-набор обрабатывается за время, приемлемое для показа жюри.
- **Воспроизводимость:** версии библиотек зафиксированы, веса модели доступны по ссылке из README, результат на проверочной выборке можно повторить.
- **Персональные данные:** на кадрах могут быть лица и номера машин. Кадры не публикуются наружу и не отправляются во внешние сервисы без согласования с организаторами (152-ФЗ). Если для оценки состояния используем внешнюю мультимодальную модель по API, отправляем только вырезку с объектом.
- **Язык интерфейса:** русский.

## 6. Что не входит в MVP

- Интеграция с внутренними системами МГТС.
- Обработка видеопотока в реальном времени.
- Мобильное приложение.
- Вход в систему и разграничение прав.
- Автоматическое размытие лиц и номеров.
- Сравнение объездов и отчёт в PDF (US10, US11), если не останется времени.
